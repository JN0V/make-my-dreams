# Make My Dreams — v0.6.b Spec: constitution suggestions + discover-then---here friction fix

> v0.6.a made MMD *run* on a third-party repo. v0.6.b makes it a *good guest* of that repo's existing rules. The user's principle (locked in the v0.6.a design conversation): **"sur un repo qui a déjà une constitution, on peut faire des suggestions d'amélioration, mais sinon elle reste."** The project owns its constitution — MMD never overwrites it — but when one exists, MMD can point out gaps.
>
> An honest scoping correction drove this slice (universal §VI): the v0.6.a HANDOVER framed v0.6.b as *"the Layer-C composer should read the project's constitution instead of MMD's bundled modules."* On inspection that is **largely moot** — on the `mmd --here` path (the third-party flow) `buildPrompt` short-circuits and the Layer-C composer is **never invoked**; the constitution that governs a `--here` build is **Layer B**, the BMAD auto-dev workflow configured with `constitution: '{project-root}/.specify/memory/constitution.md'` — i.e. **the project's own constitution already governs** (the v0.6.a AC-6 live run confirmed: *"Context loaded: constitution v1.3.0 (.specify/memory/constitution.md)"*). The composer only runs on the greenfield/profile path, which builds a fresh app in `demo/` where there is no project constitution to read. So rewriting the composer would be low-value work against a non-problem (KISS/YAGNI). The real, wanted value is the **non-destructive suggestions** feature.
>
> Surface + method (both delegated to recommendation in the design conversation): suggestions are surfaced **in the `mmd discover` report** (zero new command to learn — the user's standing preference; the report is non-destructive by nature) and generated by a **deterministic checklist** (pure, free, no network, no hallucination — matching MMD's existing pure builders: composer, handover, document-readme). An LLM-enriched mode stays a future opt-in, like `discover --infer-with-claude`. Folded in: the **discover-then---here friction** v0.6.a surfaced (discover dirties the tree → the first-run guard's dirty-tree veto trips) — fixed so the documented "run discover, read the suggestions, then `mmd --here`" flow works without a manual stash.

---

## 1. Goal of v0.6.b

```
[mmd discover on a repo that HAS a constitution]
   reads .specify/memory/constitution.md → runs a deterministic gap checklist →
   adds a "Constitution suggestions" section to mmd-discovery-report.md:
     ## Constitution suggestions (advisory — your constitution is never modified)
     Your constitution looks solid on: design principles, documentation.
     Consider adding (heuristic — MMD looked for common themes and didn't find these):
       - Testing discipline — e.g. tag tests, red→green on every failure, state coverage expectations
       - Commit & branch workflow — atomic commits, branch-first, push, conventional-commit style
       - Security practices — input validation, secrets handling, least privilege
   (NEVER edits constitution.md — "elle reste". No constitution present → no section,
    the first-run setup will materialize a sane default instead.)

[mmd discover then mmd --here]  (the documented flow)
   before:  discover writes mmd-discovery-report.md + .mmd/ → dirty tree →
            --here's first-run guard preflight refuses (exit 4). Friction.
   after:   discover .gitignores its own scratch; the guard's dirty-tree veto
            treats MMD-managed paths (.mmd/, mmd-discovery-report.md, .gitignore)
            as clean → --here proceeds. ANY real user change still refuses (F7 intact).
```

Deliverables:
1. **Deterministic suggestions checklist** (`lib/discover/constitution-suggest.js`): a pure `suggestConstitutionImprovements(constitutionText) → { present: string[], missing: Suggestion[] }` that scans the project's constitution text for common governance themes (testing, commit/git, security, error-handling, design principles, documentation, AI-coding hygiene) by keyword heuristic and reports which are present vs absent. No I/O, never throws, honest about being a heuristic.
2. **Discover surfaces the suggestions** (`lib/discover/report.js` + `bin/discover.js`): the orchestrator reads `{target}/.specify/memory/constitution.md` (if present) and passes its text to `buildReport`, which renders a **"Constitution suggestions"** section — advisory, present only when a constitution exists, explicitly stating the file is never modified. `constitution.md` is never written by discover.
3. **Discover-then---here friction fix** (`bin/discover.js` + the guard preflight in `bin/mmd.js`): discover ensures its scratch outputs (`.mmd/`, `mmd-discovery-report.md`) are `.gitignore`d in the target (idempotent, marked block); the first-run guard's dirty-tree preflight filters out MMD-managed paths (`.mmd/`, `mmd-discovery-report.md`, `.gitignore`) so a tree dirtied *only* by them counts as clean — while any non-MMD dirty path still refuses (the v0.6.a F7 protection of real user work stays intact).
4. **Validate on a real repo**: a repo with a thin constitution → discover's report lists the gaps; `discover` then `--here` runs with no manual stash. DoD-captured.

**Mission validation**: drop a deliberately thin `constitution.md` (say, only KISS + documentation) into a throwaway repo, run `mmd discover` → the report's "Constitution suggestions" section flags the missing testing/commit/security/error-handling themes and explicitly says the file is untouched; verify `constitution.md` is byte-for-byte unchanged; then run `mmd --here "<trivial>"` with no manual cleanup → it proceeds (no dirty-tree exit 4). A repo with a *rich* constitution → the section says it looks solid with few/no suggestions.

## 2. Acceptance criteria (Given / When / Then)

### AC-1: deterministic suggestions checklist (pure)
**Given** a constitution's text (a string) — rich, thin, empty, or odd
**When** `suggestConstitutionImprovements(constitutionText)` runs
**Then**: it returns `{ present: string[], missing: Array<{theme, suggestion}> }` where each governance theme MMD checks (at minimum: testing, commit/git workflow, security, error-handling, design principles [SOLID/KISS/DRY/separation], documentation, AI-coding hygiene) is classified present/absent by a case-insensitive keyword heuristic; absent themes yield a human-readable `suggestion` line (plain language, universal §VII — no MMD-internal module paths). A rich constitution → most themes present, few/no missing. An empty/whitespace string → all themes missing. A non-string/odd input → degrades to "all missing" or an empty result rather than throwing. It is PURE (no fs, no network) and stable (same input → same output). The output is explicitly framed as a heuristic (the renderer says so), never as authoritative.
Tag: `@unit` (exhaustive: rich / thin / empty / malformed).

### AC-2: discover renders the suggestions section — non-destructively
**Given** a target repo with `.specify/memory/constitution.md` present (and a separate case where it is absent)
**When** `mmd discover` runs and `buildReport` assembles the report
**Then**: when a constitution exists, the report includes a **"## Constitution suggestions"** section — an advisory note stating the constitution is never modified, the list of themes that look present, and the missing-theme suggestions from AC-1; when no constitution exists, the section is **omitted** entirely (no noise; the first-run setup handles the no-constitution case). `discover` reads the constitution but **never writes `constitution.md`** ("elle reste" — assert the file is byte-for-byte unchanged across a discover run). `buildReport` stays a pure transform: the orchestrator (`bin/discover.js`) does the read and passes `constitutionText` (or null) in. Back-compat: the rest of the report is unchanged; a missing constitution behaves exactly as today.
Tag: `@unit` (buildReport with/without constitutionText) + `@integration` (discover on a fixture with a thin constitution surfaces the section; constitution.md untouched).

### AC-3: discover-then---here works without a manual stash (friction fix, F7 intact)
**Given** a fresh repo where `mmd discover` has just run (so `.mmd/` + `mmd-discovery-report.md` are present and the tree is otherwise clean)
**When** `mmd --here "<change>"` runs and the first-run guard's dirty-tree preflight evaluates the tree
**Then**:
- `discover` has ensured its scratch outputs (`.mmd/`, `mmd-discovery-report.md`) are `.gitignore`d in the target — idempotent (re-running discover doesn't duplicate the block), within a clearly-marked `# MMD …` block, and only touching `.gitignore` (never `constitution.md` or user files).
- the guard's dirty-tree preflight treats a working tree dirtied **only** by MMD-managed paths (`.mmd/`, `mmd-discovery-report.md`, `.gitignore`) as clean → the guard proceeds to setup/run.
- **F7 stays intact**: if the tree contains **any** non-MMD-managed dirty path (a real user file), the preflight still refuses with exit 4 (so the setup's `git add -A` can never sweep the user's uncommitted work).
Tag: `@unit` (the preflight's dirty-set filter: MMD-only → clean, mixed → refuse) + `@integration` (discover → --here on a real-ish fixture proceeds; a user-dirtied file → exit 4).

### AC-4: docs + ADR
**Given** v0.6.b ships
**When** docs are read
**Then**: a new ADR documents (a) the honest scoping correction — why the composer rework was dropped (Layer-B already governs `--here` with the project's constitution; the composer is greenfield-only); (b) suggestions in the discover report via a deterministic checklist (why not LLM: pure/free/honest, matching MMD's builders; LLM enrichment deferred); (c) the non-destructive guarantee ("elle reste"); (d) the discover-scratch gitignore + the guard preflight MMD-managed filter (and that F7 stays intact). `README.md` + `CLAUDE.md` note the constitution suggestions in the `mmd discover` description. `mmd document-readme --tests N` + `mmd handover --tests N` refresh the mechanical blocks.
Tag: `@unit` anchors (ADR/README markers).

### AC-5: real-repo validation (DoD gate)
**Given** a throwaway non-MMD repo with a deliberately thin `constitution.md`
**When** the flow is run: `mmd discover` then `mmd --here "<trivial>"`
**Then**: discover's report lists the missing governance themes and states the file is untouched; `constitution.md` is verified byte-for-byte unchanged; `mmd --here` proceeds with no manual stash (no spurious exit 4) and completes a slice. Captured in HANDOVER. (The heavy real `claude -p` auto-dev is optional here — the v0.6.a AC-6 live run already proved the full --here pipeline on a third-party repo; this AC-5 focuses on the v0.6.b surfaces: suggestions + the friction fix on a real repo.)
Tag: `@e2e` (scripted/manual, documented).

## 4. Out of scope for v0.6.b (deferred unless noted)
- ❌ **Layer-C composer rework** ("read the project's constitution") — dropped as low-value: Layer B already governs `--here` with the project's constitution; the composer is greenfield-only (see the intro's honest correction). Documented in the ADR, not built.
- ❌ **LLM-enriched suggestions** (`discover --suggest-with-claude`) — a future opt-in, mirroring `--infer-with-claude`. The deterministic checklist ships first (YAGNI).
- ❌ **Auto-applying suggestions** to `constitution.md` — forbidden by design ("elle reste"). Suggestions are advisory-only, in the report.
- ❌ **Modularizing a third-party monolithic constitution** into MMD's per-module layout — not needed (Layer B reads the monolithic file fine).
- ❌ **Scale assumption**: one constitution file, a handful of themes — a small deterministic scan. No performance concern.

## 5. Implementation hints (for auto-dev)
1. Read this SPEC; `lib/discover/report.js` (`buildReport` is pure — thread a new `constitutionText` arg through; render the section between "Inferred" and "Hypotheses", or after "Hypotheses"); `bin/discover.js` (where it reads scanData and calls `buildReport` / `writeReport` — add the constitution read + the gitignore-scratch step there); and the first-run guard preflight in `bin/mmd.js` (the `preflightFn` that runs `git status --porcelain` and refuses a dirty tree — line ~459: filter the porcelain lines through a MMD-managed predicate before deciding).
2. `suggestConstitutionImprovements`: keep it a PURE function over a string. Theme detection = a small table of `{ theme, label, keywords: RegExp, suggestion }`; a theme is "present" if its keyword regex matches the text (case-insensitive), else "missing". Be conservative + honest: the renderer must label the list a *heuristic* ("MMD looked for common themes"), never authoritative. Empty/non-string → all missing (or empty), never throw.
3. The non-destructive guarantee is the heart of "elle reste": discover READS `constitution.md`, NEVER writes it. Add an integration assertion that the file's bytes are identical before/after a discover run.
4. The MMD-managed predicate for the preflight: a porcelain line is MMD-managed iff its path is `.mmd/` (or under it), `mmd-discovery-report.md`, or `.gitignore`. The preflight is clean iff EVERY dirty line is MMD-managed; otherwise refuse (exit 4) — this preserves v0.6.a's F7. Factor the predicate as a pure, unit-tested helper.
5. gitignore the scratch idempotently: append a marked block (e.g. `# MMD discovery scratch (auto-added by mmd discover)`) only if not already present; create `.gitignore` if absent; never reorder/clobber existing entries.
6. Operational rules apply to the **launch of this slice** (an `mmd --here` run): `MMD_TIMEOUT_MS=0`, commit incrementally per AC, spec-frozen directive, do not cite a to-be-created `docs/adr/*.md` path literally (describe it as "a new ADR in the ADR folder").
7. Constitution bindings: universal (§I SRP — suggestions/predicate are their own pure modules, §II KISS — deterministic not LLM, §VI honesty — heuristic labeled as such + the composer-drop documented, §VII readable suggestions), ai-coding, commit-git, testing (tag every test; red-green), error-handling (pure fns never throw; preflight degrades safely), security (discover reads a repo file — path-safety; never write constitution.md), documentation, brownfield.
