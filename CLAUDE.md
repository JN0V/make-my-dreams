# Project memory for Claude Code — Make My Dreams (MMD)

> Claude Code auto-loads this file at the start of every session opened in this repo. It propagates the project constitution to ANY skill, slash-command, sub-agent, or interactive task running in this session — not just to MMD's `auto-dev` engine.

## What this project is

Make My Dreams (MMD) is an accessibility and orchestration layer for AI-driven development. It stands on top of Spec Kit, OpenSpec, BMAD, gStack, and Ralph Loop rather than replacing them. The full design rationale lives in [`MAKE_MY_DREAMS.md`](./MAKE_MY_DREAMS.md) (16+ versions of evolving scoping) and the documented dev-by-AI problems in [`PROBLEMS.md`](./PROBLEMS.md).

## Constitution — modular, loaded by binding

The project constitution is modular (v2.0+). Modules live in `.specify/memory/constitution/`. A bindings table at `.specify/memory/constitution-bindings.yaml` tells which modules apply to a given skill, worker, engine, profile, or context.

**For an LLM working in this repo session:**

If you are about to invoke a known skill, worker, or engine, look up its required modules in `constitution-bindings.yaml` and load only those. This keeps your context lean.

If you are doing ad-hoc work and don't know which modules apply, load these baselines:

@.specify/memory/constitution/universal.md
@.specify/memory/constitution/ai-coding.md
@.specify/memory/constitution/commit-git.md

Then add as needed:
- Touching tests? `@.specify/memory/constitution/testing.md`
- Touching security-sensitive code? `@.specify/memory/constitution/security.md`
- Producing documentation? `@.specify/memory/constitution/documentation.md`
- Handling runtime errors? `@.specify/memory/constitution/error-handling.md`
- Making architectural decisions? `@.specify/memory/constitution/architecture.md`
- Working on a Kid-profile project? `@.specify/memory/constitution/safe-by-default.md` + `@.specify/memory/constitution/kid.md`

The full index of modules and their loading rules is in [`.specify/memory/constitution.md`](./.specify/memory/constitution.md).

## Constitution diffusion mechanisms

The constitution is propagated through three complementary layers:

**Layer A — Claude Code session (this file).** Anthropic auto-loads `CLAUDE.md` at session start. Any skill, slash-command, sub-agent, or interactive task spawned in this session inherits these instructions. Covers gStack skills (`/qa`, `/cso`, etc.), `/loop`, `/ralph-loop`, and Task-tool sub-agents.

**Layer B — auto-dev pipeline.** `install-mmd.sh` materializes the `auto-dev` workflow that explicitly injects the constitution into each Phase 1–4 sub-agent. Independent of this file; redundant for safety.

**Layer C — MMD CLI subprocess.** `lib/invoke-autodev.js` injects the constitution into the prompt passed to `claude -p` when MMD runs `auto-dev` headless (CI, cron, dream-bench). Required because subprocess `claude` sessions do not necessarily share the parent's CLAUDE.md.

The composer (`lib/constitution-compose.js`, **shipped v0.3.c**) turns the bindings table into a function that returns the per-invocation module bundle as a string ready for prompt injection. `parseBindings` (hand-rolled YAML-lite, no external dep) reads `constitution-bindings.yaml`; `resolveModules({profile}, bindings)` resolves `MMD_PROFILE` to `defaults.always ∪ profiles[profile]` (deduped, deterministic); `composeConstitution({profile})` reads each `.specify/memory/constitution/<name>.md` and concatenates them under per-module headers. `buildPrompt` injects that block when `MMD_PROFILE` is set — so a Kid build carries the real `safe-by-default.md` + `kid.md` text and a Pro build carries `pro.md` — and falls back to a minimal line if the bindings/modules are unreadable (graceful, never crashes). Currently composes by **profile** only; engine/context/skill dimensions are a future slice (the resolver is built to extend). See [ADR-024](./docs/adr/024-constitution-composer-layer-c.md).

## Working agreements in this repo

- **Branch first**: never commit directly to `main` for non-trivial work. See `commit-git.md` for naming conventions.
- **Push immediately**: after every commit, `git push`. Uncommitted-and-unpushed work doesn't exist.
- **Red-green for every failure**: any failure (test, install script, pipeline, integration) triggers a deterministic red→green test pass before it's considered fixed. See `testing.md`.
- **Test stratification**: tag every test you write (`@smoke`, `@unit`, `@integration`, `@e2e`). See `testing.md` §V.
- **AI honesty**: report walls explicitly, don't fabricate success. See `ai-coding.md` §I.

Use it when the slice's correctness must be guarded by an oracle the implementing agent cannot edit. See [ADR-026](./docs/adr/026-sealed-test-oracle.md). The sealed pipeline also logs a **blast radius** to `status.json.blast_radius`; as of v0.4.c this is **import-graph accurate** (not a grep stub) — `lib/sealed-tests/import-graph.js` parses + resolves module specifiers and records the transitive reverse closure (every file that imports a changed file directly or through a chain), with **zero new dependencies** (vanilla-stack) and a documented residual gap (computed/runtime specifiers, re-export aliasing, non-JS importers). - **Documentalist coherence graph — staleness-on-diff (`mmd document-review --since <ref>`, v0.7.d)**: the structural answer to "change one of doc/code/ADR, know the other two need a look." `mmd document-review --since <ref>` takes the slice's diff (`git diff --name-only <ref>`), walks a **derived** file-level coherence graph from the changed files, and prints a ranked, **advisory** **"## Coupled changes"** report to **stdout** — *"change one node, learn which neighbors to review"*. **Derive, never maintain** (the golden rule — a hand-kept map rots): the graph is composed from edges that already exist for free — `computeBlastRadius` (ADR-027) gives code↔code import edges, the v0.7.b `lib/documentalist/doc-refs.js` gives doc→code refs, and the new doc-links extractor gives doc↔doc. Two new **pure** modules: `lib/documentalist/doc-links.js` (`extractDocLinks(text, {docPath, resolveAdr})` → doc↔doc edges: `[[wiki]]` links, `ADR-NNN` resolved to the real ADR file via an injected resolver else a number-keyed stem, relative `.md` links; conservative — external/absolute/anchor/code links yield no edge; never throws) and `lib/documentalist/coherence-graph.js` (`buildCoherenceGraph({importEdges, docToCodeEdges, docLinkEdges})` → a **file-level, bidirectional** adjacency, each edge keeping its `kind` import/doc-ref/doc-link; `coupledNeighbors(graph, changedFiles)` → per changed file, neighbors **ranked strong (direct) before weak (2-hop transitive)**, deduped, excluding the changed set; pure, deterministic, never throws). The `--since` mode in `bin/documentalist/document-review.js` is a **standalone READ-ONLY query**: it returns before any roadmap read or report write — it does **NOT** rewrite `docs/coherence-review.md` (asserted: clean tree after a run), and the no-flag dashboard path stays byte-for-byte unchanged; a bad/unknown ref or non-git repo → honest **exit 5**, `--since` with no value → exit 2. **Precision-first** (the v0.7.b discipline — a graph that cries wolf is useless): edges are kept **only to real tracked files** (no phantom neighbors), and **hub suppression** means a high-degree node (CLAUDE.md/HANDOVER.md reference dozens of ADRs) is reported as a direct neighbor but **not** used as a transit node for weak edges, so a change near it doesn't weak-flag the whole repo. **Advisory + ranked, never a hard gate** (coupling ≠ certainty — review, don't obey). It is exactly what would have caught the v0.7.c coupled-test break (the moved SPECs ↔ the inventory test) *before* it went red. Symbol-level granularity, the semantic `@mmd:link` anchor, the Mermaid/.dot mind-map, and git co-change edges are deliberately **deferred** (file-level + the diff check is ~80% of the value). See [ADR-037](./docs/adr/037-coherence-graph-staleness.md).
- **Coherence graph — cap the hub-SOURCE flood (`mmd document-review --since`, v0.7.e)**: a precision refinement to the v0.7.d staleness report. v0.7.d already suppressed hub *transit* (it does not traverse weak/transitive edges THROUGH a high-degree doc like CLAUDE.md/HANDOVER.md, so a change *near* a hub doesn't flag the whole repo). v0.7.e adds the symmetric face: when the file a diff changed **is itself the hub** (you edit CLAUDE.md), every one of its dozens of direct references used to be reported as `strong`, flooding the "Coupled changes" report with 40+ lines — which, per the v0.7.b discipline, flags nothing. Now the pure `coupledNeighbors` (`lib/documentalist/coherence-graph.js`) detects a **hub source** (direct degree > `HUB_DEGREE`, the existing threshold, now exported), **caps it to the top `HUB_DEGREE` ranked direct neighbors** (cut taken AFTER the deterministic strong→kind→path sort, so the kept slice is the highest-ranked), **records the dropped count** on the entry (`hubSuppressed`, added ONLY when capping — an ordinary entry keeps its exact `{file, neighbors}` shape, back-compat), and **skips the transitive layer** for it (weak edges atop a flood are pure noise). `renderCoupledChanges` (`bin/documentalist/document-review.js`) prints an **honest** `… +N more direct neighbors suppressed (hub source — …)` note — never a silent truncation (universal §VI). A non-hub `--since` run is **byte-for-byte v0.7.d's** (asserted). Both faces reuse the one `HUB_DEGREE` lever: a hub couples to too much to be an actionable hint, whether it is *near* the change or *is* the change. Per-kind/configurable thresholds stay deferred (YAGNI). See [ADR-038](./docs/adr/038-coherence-graph-hub-source-cap.md).
- **`/mmd` operator slash command (v0.7.5)**: the MMD operator playbook, encoded as a Claude Code slash command so a user — or Claude — can drive MMD by intent from a session without remembering the CLI incantations or the hard-won operational rules. `/mmd <intent>` instructs the session to **route** the intent: **(a) a code change for the current repo** → launch `mmd --here` **detached** via `setsid` (L-001) with every operational rule applied (`MMD_TIMEOUT_MS=0` so the 30-min default can't kill a real slice — L-016, bun + node 20 on `PATH`, a human-readable `--label` slug — universal §VII, `MMD_DREAM_MAX_LEN=4000`, the dream told to **commit incrementally per AC** — L-019, and the spec-frozen directive when a frozen SPEC is cited), then set up a **per-run watcher** and monitor honestly via `status.json` state + git commits — NOT the buffered redirect log (L-002, `claude -p` doesn't flush in real time), reporting honestly (ai-coding §I) and, on green, **offering** (never silently performing) a fast-forward-only merge + an annotated tag; **(b) a greenfield dream** → `mmd "<dream>"`; **(c) a bare subcommand** (`discover`, `serve`, `document-review`, `handover`, …) → `mmd <subcommand>` directly. - **Test Curator — `mmd test-health` (v0.7.6)**: the test analog of the Documentalist, but for **tests not docs** — and **DISTINCT** from the two roles it keeps getting confused with: `mmd qa` reviews *a single change* (per-diff correctness, fix-oriented); the BMAD TEA (Murat) designs *test architecture* for a feature ahead of time. `mmd test-health` owns the fourth question neither answers: **is the test _corpus itself_ healthy as it grows?** It is **detect-and-report only** (strictly read-only — it **NEVER modifies a test**) and **deterministic** (no `claude` spawn — the corpus signal is exactly computable, so an LLM would add cost + non-determinism for no gain; contrast `document-review --with-claude`). It gathers the git-tracked test files (`git ls-files '*.test.js'`, **excluding `test/fixtures/`** — those are inputs to the discover tests, not MMD's own corpus), scans each test's **title** for the stratification tag (`@smoke`/`@unit`/`@integration`/`@e2e` prefix, the same convention `npm test:smoke` greps + testing.md §V mandates), and writes EXACTLY `docs/test-health.md` (the test analog of `docs/coherence-review.md`; an `@integration` test asserts no other tracked path changes — the read-only safety heart, mirroring `document-review`). The report surfaces the **stratification distribution**, the **untagged tests** (a §V violation, listed with `file:line` — the first live run on MMD flagged **73** real ones in older files), a **smoke-health line** (count vs the §V 5–10 fast-feedback band — thin/usable/over-budget), and **oversized files** (over `MMD_TEST_FILE_MAX_LINES` default 500 OR `MMD_TEST_FILE_MAX_TESTS` default 60 — env-overridable, validated with graceful honest fallback) as split candidates. Honest advisory framing throughout, clearly a **heuristic** not an audit. Detect-before-act: it **names** the debt (e.g. the 73 untagged) but never auto-retags — a wrong stratum is worse than an absent one (it corrupts the fast lane), so closing the debt is a separate human-reviewed action (the same earn-trust-then-act arc the Documentalist took in v0.7.a→c). Pure `scanTestCorpus` + `buildTestHealthReport` in `lib/test-curator/{scan,report}.js` (never throw, deterministic); the thin coordinator in `bin/test-curator/test-health.js`; dispatch + USAGE + `SUBCOMMANDS` mirror the document-* contract. See [ADR-040](./docs/adr/040-test-curator-test-health.md).
- **Test Curator redundancy face — `mmd test-health` (v0.7.7)**: the Test Curator's **second face**, answering *which tests likely **overlap**, so the corpus can be pruned?* (ADR-040 deferred "duplicate-test detection"; now built). Same contract as the stratification face — **deterministic** (no `claude`), **advisory**, and **DETECT-BEFORE-CUT**: it **NEVER deletes a test** (a similar-looking test may document a distinct intent — the **human decides**). Method = **clustering by target + structural similarity, NOT coverage** (a coverage mode needs an instrumented run — non-deterministic, breaks the read-only/pure contract — so it stays a **deferred opt-in**). The report's new **"Redundancy candidates"** section lists (a) **near-duplicate test pairs** — each test's *body* (the code between the callback braces, captured by a deterministic brace-depth scan that skips strings/comments in `lib/test-curator/extract-bodies.js`) is normalized (comments+whitespace stripped, tokenized), turned into k-gram **token shingles**, and scored by **Jaccard similarity** ≥ `MMD_TEST_DUP_SIMILARITY` (default **0.9**, in (0,1], graceful fallback); and (b) the **most-tested modules** as **over-test candidates**, clustering test files by the `lib/`/`bin/` modules they import (extracted per file). **Bounded** — pairs are compared **within-file only** (same file ⇒ same target cluster, so no global quadratic blow-up over ~1760 tests); the cluster view needs **zero** pairwise work. **Precision-first** (no crying wolf): the high 0.9 default + a small token floor (trivial stub bodies skipped) yield **3** real pairs on MMD (0.91–0.95), not a flood; the most-tested module is `lib/invoke-autodev.js` (204 tests / 33 files). Long lists are capped with an **honest "+N more"** note (no silent truncation, universal §VI). Documented heuristic residual: an import line written inside a *fixture string* in a test file is counted as a target (same class as the v0.7.6 `test(`-in-a-string note). Pure `nearDuplicatePairs` + `targetClusters` in `lib/test-curator/redundancy.js`; `scan.js` attaches `body`+`targets` additively; `report.js`+the bin render the section and stay **strictly read-only beyond `docs/test-health.md`** (asserted). See [ADR-041](./docs/adr/041-test-curator-redundancy-detection.md).
- **Test Curator goes POLYGLOT — `mmd test-health` (v0.8.0)**: the fix for a **correctness failure** — the Test Curator was **secretly JavaScript-only** (it hard-wired `test()`/`it()`, the `@`-tag convention, `import`/`require` + `lib/`/`bin/` targets, brace bodies, `*.test.js`), so on a **Rust/Python/Go/C** repo it found nothing or **fabricated** numbers — a direct violation of MMD's any-technology mission and the brand-new **constitution §VIII (technology-agnostic analysis, NON-NEGOTIABLE)**. The fix is MMD's **"orchestrate, don't reimplement"** shape: a **generic, language-neutral core** + per-technology **adapters**. **The core imports NO adapter and contains NO language syntax** (`lib/test-curator/redundancy.js` similarity/clustering, `lib/test-curator/report.js` render — they operate ONLY on normalized entries). **Adapters** live in `lib/test-curator/adapters/`: `index.js` is the **documented contract** (`id`, `displayName`, `matches(signals)`, `discoverTests({repoRoot,files,readFile})` → normalized entries `{file,line,title,stratum|null,body|null,targets|null}` + per-file metrics + **capability flags** `supportsBodies`/`supportsStratification`/`supportsCoverage`) + the **pure registry** (`resolveAdapters(signals)` returns ALL matching adapters from manifest presence — `package.json`→JS, `pyproject.toml`/`setup.py`/`requirements.txt`→Python, `Cargo.toml`→Rust, `go.mod`→Go — `[]` when none; plus `detectStackNames` naming even unsupported stacks and `supportedStackNames`). `adapters/javascript.js` is the **existing** scan/extract/`@`-tag/target logic behind the contract — **zero behavior change** for a JS repo (MMD self-run is byte-identical: 1774 tests, 187 files, same strata/bodies/targets/pairs/clusters; only the `tag`→`stratum` rename + genericized prose differ), with all JS assumptions (and its JS-internal `scan.js`/`extract-bodies.js`) living HERE. `adapters/python.js` is the **proof of genericity** — discovers pytest/unittest `def test_*` (functions + methods), pytest-marker strata, `import`/`from` project targets; declares **`supportsBodies:false` honestly** (clustering + stratification still work, redundancy pairs marked **not-available** — never a silent ✅-none). **Dependency direction: core ← adapters ← `index` ← bin.** The bin (`bin/test-curator/test-health.js`) runs the **§VIII honest gate**: detect the stack(s) → run every matching adapter → aggregate → write `docs/test-health.md`; when **NO adapter matches**, **REFUSE honestly** — name the detected stack + supported list, **exit 6, NO report, NO fabricated numbers** (the rule that stops the JS-on-Rust bug); a **mixed** repo analyzes the supported stacks and **names** the unsupported ones. **Coverage stays deferred for ALL adapters and will be polyglot** (each adapter's native tool → lcov/cobertura — NOT `node --test` baked into the core). The same §VIII reckoning is queued for blast-radius / coherence-graph / doc-refs (also JS-specific). See [ADR-042](./docs/adr/042-polyglot-test-curator-adapters.md).
