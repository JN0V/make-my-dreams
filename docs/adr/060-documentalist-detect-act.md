# ADR-060: Documentalist detect + act — MOVE the surplus, DELETE the false/deprecated

Date: 2026-06-07
Status: Accepted

## Context

A live audit of MMD's own `README.md` (Sébastien, 2026-06-06) found three defects
the Documentalist sailed straight past:

1. **A prose capability-lie.** The README's opening claimed *"MMD adds … local
   parallelization via git worktrees"* — but worktrees parallelization is
   **unbuilt** (the deferred v0.9 "Parallel Conductor + worktrees"). A flat
   falsehood in the very first paragraph.
2. **A freshly-deprecated surface still taught as primary.** v0.19 made
   `handover` / `document-readme` / `document-review` / `document-compact`
   deprecated aliases of `mmdream document`, yet the README still taught them as
   the primary commands (39 mentions, full how-to sections, usage code-fences).
3. **Structure / length.** 918 lines (4.6× the §6.4 200-line cap), a 739-line
   `## Usage` wall, the changelog inline, Quick start buried at line 905.

The diagnosis: this is **what you get WITHOUT a real Documentalist**. The v0.7–v0.20
Documentalist only refreshed marker-bounded mechanical blocks and detected a NARROW
drift (dangling refs, counts, a tiny curated deprecated set, version promises). It
had **no muscle** for a capability-lie, a deprecated-as-primary surface, or
structure/length — and, critically, it only ever **detected**; it never **acted**
on the conciseness debt (v0.19 deliberately deferred "the risky semantic
conciseness" to "a v0.21 branch+oracle path").

A first v0.21 attempt shipped with a correctness bug worth recording as the reason
for this ADR's central invariant: it moved the `## History` narrative into a file
named `CHANGELOG.md` and left a stub that called the History "the changelog" — a
content/destination/stub mismatch that produced a *new* falsehood while condensing.

## Decision

Give `mmdream document` **three new deterministic detections** and a
**two-operation action model**, role-aware and precision-first.

### Two operations, chosen by the NATURE of the content

- **Surplus** (true but verbose — a condensation problem): **MOVE** it to a linked
  sibling file, **byte-lossless**. Nothing true is lost; the landing doc just gets
  shorter. (`## History` → `docs/<stem>-history.md`; `## Usage` → `docs/<stem>-usage.md`;
  the genuine changelog → `CHANGELOG.md`.)
- **False / deprecated / no-longer-current**: **DELETE** it outright. *Relocating a
  lie is pointless.* You cannot lose *true* information by erasing *false*
  information. (The worktrees claim is removed; a deprecated-as-primary mention is
  removed where clean.)

Both are **deterministic** (no `claude` — every signal is exactly computable). The
only safety line is **precision** (the secret-scan / deps-gate shape — *high-
confidence acts, uncertain only advises*): a HIGH-confidence finding is auto-removed
ONLY when it can be excised cleanly (a whole line, a discrete list item, or a
trailing comma-clause whose separator is fixed); a removal that would malform prose
(a falsehood buried mid-sentence) is **FLAGGED for review**, never mutilated.
Everything runs through git (reversible) and the drift detector re-validates the
doc afterward (no new dangling refs, still well-formed).

### The TRUTHFUL-STUB + CONTENT-MATCHED-DESTINATION invariant (the bug this fixes)

A section's destination filename MUST reflect its **content**, and the stub's link
**text** MUST be the section's own heading. A `## History` section goes to
`docs/<stem>-history.md` with a stub *"See [History](…) for the full history"* —
**NEVER** a file named `CHANGELOG.md`, **NEVER** a stub that calls it "the
changelog". The changelog is identified by its `mmd:readme:changelog` **marker** (or
a `## Changelog` heading), not "the first/biggest section"; only the genuine
changelog may target `CHANGELOG.md`. Two pure helpers — `destinationForSection(heading, docPath)`
and `stubLineFor(heading, dst)` — make this checkable in unit tests.

### The changelog special-case (marker-owned block)

The README's `## Changelog` is a `mmd:readme:changelog`-marker block regenerated by
the mechanical-refresh step. Moving it relocates the **markers AND content** to
`CHANGELOG.md`, leaves a truthful link in the README, and the **mechanical-refresh
follows the marker to its new home** — so the changelog is maintained in
`CHANGELOG.md` and the README stays a link (idempotent; never stuck inline). This is
the one section the planner relocates despite being marker-owned, because its
generator is taught to follow it.

### Role-aware, not blanket (§VIII / L-009)

Every check + both actions operate on ANY markdown doc, driven by a doc's **role**:
a landing/concise doc (README) has a tight budget and gets condensed; a **reference**
doc (`MAKE_MY_DREAMS.md`, an ADR, a SPEC) is *legitimately* long and is NEVER
condensed. No "shard everything over cap".

### Derive, don't hand-curate (v0.7.d golden rule)

The deprecated set is **derived from the real `[DEPRECATED]` notices** the CLI
emits (parsed from the alias bin files), not a hand list — so when a command is
un-deprecated or a new one is deprecated, the doc-check follows the code. The
unbuilt/built classification reuses `roadmap-reconcile` so a capability-lie trigger
goes silent the day the capability ships.

### Self-reference fix

The mechanical-block generators (`lib/handover/*`, the README Status builder) wrote
self-referential instructions naming the **deprecated** aliases; they now name
`mmdream document`, so the blocks MMD itself regenerates no longer teach a
deprecated surface.

## Consequences

- **The exact defects Sébastien spotted are fixed by the agent itself**: the
  worktrees capability-lie is **deleted**, the deprecated `document-*` surface is
  removed/flagged, the README is condensed **losslessly** (changelog → `CHANGELOG.md`,
  History → `docs/readme-history.md`, Usage → `docs/readme-usage.md`), and a
  reference doc is correctly left long.
- `mmdream document --check` grows **teeth**: it now also fails (exit 1) on a
  capability-lie / deprecated-surface finding.
- `--dry-run` previews everything and leaves a **clean tree**; the v0.19
  read-only-beyond-its-writes invariants are preserved.
- Pure planners/checkers split from the I/O (SRP), never throw, labelled
  heuristics; atomic commits (move / delete / refresh separate, L-019).
- **Deferred** (Out of scope): LLM prose-beautification (rewriting true-but-wordy
  prose tighter), detecting general "obsolete narrative" beyond the high-confidence
  categories, auto-removing a mid-sentence falsehood (flagged here — needs the LLM
  pass), generic reference-doc sharding, and a smart role classifier (role is
  heuristic-by-filename for now).

## Live result (AC-6)

Running `mmdream document` on MMD's own README condensed it from **918 lines** to a
budget-sized landing doc, moved the History narrative to `docs/readme-history.md`
and the changelog to `CHANGELOG.md` (each stub link text matching its target),
removed the worktrees capability-lie, and regenerated the mechanical blocks naming
`mmdream document` — with no new dangling references and valid markdown after.
