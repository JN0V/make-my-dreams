# Project memory for Claude Code — Make My Dreams (MMD)

> Claude Code auto-loads this file at the start of every session opened in this repo. It propagates the project constitution to ANY skill, slash-command, sub-agent, or interactive task running in this session — not just to MMD's `auto-dev` engine.

## What this project is

Make My Dreams (MMD) is an accessibility and orchestration layer for AI-driven development. It stands on top of Spec Kit, OpenSpec, BMAD, gStack, and Ralph Loop rather than replacing them. The full design rationale lives in [`MAKE_MY_DREAMS.md`](./MAKE_MY_DREAMS.md) (16+ versions of evolving scoping) and the documented dev-by-AI problems in [`PROBLEMS.md`](./PROBLEMS.md).

## Constitution — modular, loaded by binding

The project constitution is modular (v2.0+). Modules live in `.specify/memory/constitution/`. A bindings table at `.specify/memory/constitution-bindings.yaml` tells which modules apply to a given skill, worker, engine, profile, or context.

**For an LLM working in this repo session:**

If you are about to invoke a known skill, worker, or engine, look up its required modules in `constitution-bindings.yaml` and load only those. This keeps your context lean.

If you are doing ad-hoc work and don't know which modules apply, load these baselines:

@.specify/memory/constitution/universal.md
@.specify/memory/constitution/ai-coding.md
@.specify/memory/constitution/commit-git.md

Then add as needed:
- Touching tests? `@.specify/memory/constitution/testing.md`
- Touching security-sensitive code? `@.specify/memory/constitution/security.md`
- Producing documentation? `@.specify/memory/constitution/documentation.md`
- Handling runtime errors? `@.specify/memory/constitution/error-handling.md`
- Making architectural decisions? `@.specify/memory/constitution/architecture.md`
- Working on a Kid-profile project? `@.specify/memory/constitution/safe-by-default.md` + `@.specify/memory/constitution/kid.md`

The full index of modules and their loading rules is in [`.specify/memory/constitution.md`](./.specify/memory/constitution.md).

## Constitution diffusion mechanisms

The constitution is propagated through three complementary layers:

**Layer A — Claude Code session (this file).** Anthropic auto-loads `CLAUDE.md` at session start. Any skill, slash-command, sub-agent, or interactive task spawned in this session inherits these instructions. Covers gStack skills (`/qa`, `/cso`, etc.), `/loop`, `/ralph-loop`, and Task-tool sub-agents.

**Layer B — auto-dev pipeline.** `install-mmd.sh` materializes the `auto-dev` workflow that explicitly injects the constitution into each Phase 1–4 sub-agent. Independent of this file; redundant for safety.

**Layer C — MMD CLI subprocess.** `lib/invoke-autodev.js` injects the constitution into the prompt passed to `claude -p` when MMD runs `auto-dev` headless (CI, cron, dream-bench). Required because subprocess `claude` sessions do not necessarily share the parent's CLAUDE.md.

The composer (`lib/constitution-compose.js`, **shipped v0.3.c**) turns the bindings table into a function that returns the per-invocation module bundle as a string ready for prompt injection. `parseBindings` (hand-rolled YAML-lite, no external dep) reads `constitution-bindings.yaml`; `resolveModules({profile}, bindings)` resolves `MMD_PROFILE` to `defaults.always ∪ profiles[profile]` (deduped, deterministic); `composeConstitution({profile})` reads each `.specify/memory/constitution/<name>.md` and concatenates them under per-module headers. `buildPrompt` injects that block when `MMD_PROFILE` is set — so a Kid build carries the real `safe-by-default.md` + `kid.md` text and a Pro build carries `pro.md` — and falls back to a minimal line if the bindings/modules are unreadable (graceful, never crashes). Currently composes by **profile** only; engine/context/skill dimensions are a future slice (the resolver is built to extend). See [ADR-024](./docs/adr/024-constitution-composer-layer-c.md).

## Working agreements in this repo

- **Branch first**: never commit directly to `main` for non-trivial work. See `commit-git.md` for naming conventions.
- **Push immediately**: after every commit, `git push`. Uncommitted-and-unpushed work doesn't exist.
- **Red-green for every failure**: any failure (test, install script, pipeline, integration) triggers a deterministic red→green test pass before it's considered fixed. See `testing.md`.
- **Test stratification**: tag every test you write (`@smoke`, `@unit`, `@integration`, `@e2e`). See `testing.md` §V.
- **AI honesty**: report walls explicitly, don't fabricate success. See `ai-coding.md` §I.
- **Sealed self-dev (optional, v0.4.b)**: a MMD slice MAY now be launched with `mmd --here --sealed "<change>"`. An independent tester writes blind acceptance tests into the gitignored `.mmd/shared/sealed-tests/`, MMD seals them by hash, auto-dev implements on the slice branch, and MMD fails the slice (exit 6, files named) if any sealed test was weakened or deleted (anti-P-04, L-023). Use it when the slice's correctness must be guarded by an oracle the implementing agent cannot edit. See [ADR-026](./docs/adr/026-sealed-test-oracle.md). The sealed pipeline also logs a **blast radius** to `status.json.blast_radius`; as of v0.4.c this is **import-graph accurate** (not a grep stub) — `lib/sealed-tests/import-graph.js` parses + resolves module specifiers and records the transitive reverse closure (every file that imports a changed file directly or through a chain), with **zero new dependencies** (vanilla-stack) and a documented residual gap (computed/runtime specifiers, re-export aliasing, non-JS importers). See [ADR-027](./docs/adr/027-import-graph-blast-radius.md), L-024. As of **v0.4.d** the sealed pipeline adds a **behavioral judge** (`lib/sealed-tests/judge.js`, P-09) that runs **after** the deterministic sealed-test gate passes: a `claude -p` oracle grades the implementation against *what was asked* (the dream/ACs) and emits a tagged per-AC verdict. All ACs `MET` → proceed; any `NOT-MET`/`UNCERTAIN` (or an unparseable reply → the sacred `uncertain` fallback, never a fabricated `met`) → **exit 7 (behavioral-gap)**, slice not marked done, verdict written to `status.json.judge`. **Exit 7 is distinct from the tamper/seal exit 6** (a tampered seal still exits 6 *before* the judge runs), so "tests went red / check attacked" (6) and "tests green but behavior misses the ask" (7) are distinguishable. See [ADR-028](./docs/adr/028-llm-judge-behavioral-oracle.md), L-025.
- **Conductor notifications (opt-in, v0.5.a)**: a detached run (`setsid … mmd --here "<change>"`) now **pushes** a signal when it ends instead of leaving you to poll. Set **`MMD_NOTIFY_URL`** (e.g. `https://ntfy.sh/<your-topic>`) and MMD POSTs a small JSON `{event,slice,state,summary,ts,message}` on run **done/failed** (`event ∈ {run_done, run_failed}`) to your own sink — ntfy/Slack/Discord/custom. It is **opt-in** (unset → no payload, no network call, default unchanged) and **best-effort** (a dead URL / non-2xx / timeout logs one line and is dropped — the run's exit code and `status.json` are **never** affected; the send is bounded by a ~5 s timeout). Payload is **run metadata only** — no secrets/env/file contents (least-disclosure egress to *your* sink). Pure core + injected sender in `lib/conductor/notify.js` (`shouldNotify` / `buildNotification` / `sendNotification`); wired into both the greenfield and `runHereMode` completion paths in `bin/mmd.js`. First brick of the v0.5 **Conductor**; the `stream-json` context monitor + 70% auto-handoff are deferred to v0.5.b (they change the spawn). See [ADR-029](./docs/adr/029-conductor-notifications.md), L-026.
- **Live context monitor (opt-in, v0.5.b)**: `mmd --monitor "<dream>"` (and `mmd --here --monitor`) makes the Conductor **see** the orchestrator's context filling up. It spawns auto-dev as `claude -p … --output-format stream-json --verbose`, parses each event's `usage` live (`input_tokens + cache_read_input_tokens + cache_creation_input_tokens`), looks up the window from the model id (a **`[1m]`** suffix → 1,000,000; known model → 200,000; unknown → 200,000 `estimated:true` — never a fabricated %), and writes the running **max** to `status.json.context = {model,window,tokens,pct,estimated}`. The tee is re-rendered **human-readable** (assistant text + periodic `[monitor] context X% (tokens/window)` lines, NOT raw JSON; `MMD_QUIET=1` respected). At **`MMD_HANDOFF_THRESHOLD`** (default `0.70`, custom value in `(0,1]` honored) it writes a `READY_FOR_HANDOFF` marker, logs a line, and fires a **`context_70`** notification **once** (debounced, reusing the v0.5.a `MMD_NOTIFY_URL` fan-out) — it does **not** stop the run (no auto-handoff yet). **Opt-in is safety-critical**: the default text spawn is the path `mmd --here` uses to build MMD itself, so it stays **byte-for-byte unchanged** (the default args carry no `--output-format`, pinned by a test). It is the **orchestrator's** context, not per-sub-agent. Pure parse/math in `lib/conductor/stream-parse.js` (`parseStreamEvent`/`contextWindowFor`/`contextTokens`/`contextPct`); the monitored spawn + readable re-render in `lib/invoke-autodev.js` (`buildAutodevArgs`/`makeMonitorConsumer`); the status writes + 70% signal/notify in `bin/mmd.js`. Second brick of the v0.5 **Conductor**; the actual auto-handoff/resume stays future. See [ADR-030](./docs/adr/030-live-context-monitor.md), L-027.
- **Context gauge in `mmd serve` (opt-in, v0.5.c)**: the v0.5.b monitor is now **visible** to the non-technical web user. `mmd serve`'s dream form gains a **"Monitor context (advanced)"** checkbox; ticking it appends `--monitor` to the web launch and the progress view shows a live **context gauge** — a bar (% of the window), humanized `tokens / window` (`337000→337k`, `1000000→1.0M`), the model, a fixed 70% threshold marker, and a "⚠️ ready for handoff" badge iff `context.ready_for_handoff`. The page **polls** `GET /api/status/<slug>` every ~3 s while a monitored job runs and re-draws the gauge from the response's `.context` (polling over SSE-push so the gauge is **decoupled** — a failed/slow poll is swallowed and **never breaks the page or the SSE stream**). `GET /api/status/<slug>` now surfaces `status.json.context` (`{model,window,tokens,pct,estimated}` with the sibling `ready_for_handoff` folded into a boolean) — additive, omitted when absent, malformed status behaves as before. **Opt-in is the safety contract**: unticked (default) → no `monitor` in the launch body → spawn args **byte-for-byte today's** (no `--monitor`/`--output-format`, pinned by a test) → no gauge, no extra polling, SSE unchanged. Strict boolean validation (`monitor` junk → false) on both launch routes (`POST /api/dream` + the catch `/confirm`). Pure render in `bin/serve-ui/gauge.js` (`renderGauge`/`humanizeTokens`, also unit-tested in node); the status fold + `--monitor` threading (`buildMmdAutodevArgs`) + served `/gauge.js` in `lib/server.js`; the checkbox/gauge/poll glue in `bin/serve-ui/{index.html,app.js,style.css}`. Gauge markup is CSP-safe (native `<progress>` + external-CSS 70% marker; the page runs under `style-src 'self'`). Third user-facing step of the v0.5 **Conductor**; auto-handoff still future. See [ADR-031](./docs/adr/031-serve-ui-context-gauge.md), L-027.
- **Using MMD on your own repo (third-party readiness, v0.6.a)**: MMD now works on a repo other than itself, with **no new command to learn**. `mmd discover` **names the stack it scanned** — a real Node/Python/Go/Rust app reports the new **`brownfield-app`** case (`lib/discover/classify.js`), distinct from `blank` (a genuinely empty/unstructured repo; `already-onboarded`/`rich`/`bmad-alone` still win, malformed input still degrades to `blank`). And the first `mmd --here` on an unprepared repo runs a **transparent first-run setup guard** (`lib/onboarding/`: pure `detectMmdSetup` probe + injected-dep `runFirstRunSetup` + pure `buildOnboardingCheatsheet`), wired into `runHereMode` right after the `Mode: --here` line and **before** the onboarding gate: **TTY** → one confirm (`Run setup now? [o/N]`) then spawn `install-mmd.sh <target>` + print the env-var cheat-sheet + proceed; **non-TTY** (`serve`/CI) → auto-run + honest log; **decline or runner failure** → **exit 8** (a new rung — NEVER an inert launch); **`MMD_SKIP_SETUP=1`** bypasses (mirrors `MMD_SKIP_GROUNDING`); **already-ready** → no-op and an **existing `.specify/memory/constitution.md` is never overwritten** ("elle reste"). The cheat-sheet surfaces the operational tribal knowledge (`MMD_TIMEOUT_MS=0`, the spec-frozen dream directive, commit-per-AC, `--sealed`/`--monitor`/`MMD_NOTIFY_URL`). The deeper "the build reads the *project's* constitution" composer rework (Layer C) is the deferred **v0.6.b**. See [ADR-032](./docs/adr/032-transparent-first-run-setup.md).
- **Considerate guest of a third-party constitution (v0.6.b)**: on a repo that **already has** a constitution, `mmd discover` now adds an advisory **"Constitution suggestions"** section to `mmd-discovery-report.md` — a **deterministic, pure** keyword checklist (`lib/discover/constitution-suggest.js`: `suggestConstitutionImprovements(text) → {present[], missing[{theme,suggestion}]}`) over common governance themes (testing, commit/git, security, error-handling, design principles, documentation, AI-coding hygiene). It is **honest about being a heuristic** (the renderer labels it so, never an audit), pure/no-I/O/never-throws (empty/malformed → all-missing), and **never writes `constitution.md`** — *"elle reste"* (an integration test asserts the file is byte-for-byte unchanged across a discover run). No constitution present → the section is omitted (the v0.6.a first-run setup materializes a default instead); LLM-enriched suggestions are a deferred opt-in (`--suggest-with-claude`, YAGNI). `bin/discover.js` does the read + threads `constitutionText` into the pure `buildReport`. **The discover-then-`--here` friction is fixed**: discover gitignores its own scratch (`.mmd/`, `mmd-discovery-report.md`) via an idempotent marked block, and the first-run setup preflight in `bin/mmd.js` treats a tree dirtied **only** by MMD-managed paths (`.mmd/`, `mmd-discovery-report.md`, `.gitignore` — pure predicate in `lib/onboarding/mmd-managed.js`) as clean, so the documented flow needs no manual stash; **any non-MMD dirty path still refuses with exit 4** (v0.6.a F7 intact — the setup's `git add -A` can never sweep real user work). The **Layer-C composer rework was retired, not built** (honest correction, universal §VI): `--here` is already governed by the *project's* constitution via **Layer B** (the BMAD auto-dev workflow reads `.specify/memory/constitution.md` directly); the composer only runs on the greenfield `demo/` path where no project constitution exists. See [ADR-033](./docs/adr/033-constitution-suggestions-and-discover-friction.md).
- **Documentalist coherence review (`mmd document-review`, v0.7.a)**: the first brick of the §6.4 **Documentalist**, built **detect-first and report-only**. `mmd document-review` answers *"what did MMD design vs what did it become, and where have the docs drifted?"* by gathering a **deterministic inventory** of MMD's real surface (`lib/documentalist/inventory.js`: subcommands, git tags, ADRs+titles, `lib/` modules, per-doc line counts with a 200-line §6.4 cap flag, root `SPEC_V*.md` sprawl count, active-lesson count — injected fs readers, **never throws**, degrades each field to empty/null), **reconciling** it against the `MAKE_MY_DREAMS.md` §9 roadmap (`lib/documentalist/roadmap-reconcile.js`: a PURE `reconcileRoadmap({roadmapText,inventory})` that parses `### vX.Y — Title` headers and classifies each capability **built/partial/unbuilt** by name-matching against the inventory — a **clearly-labelled heuristic, not an audit**; conservative: single fully-matched concept → built, half-matched compound → partial, no signal → unbuilt; malformed → unknown, never throws), and **rendering** (`lib/documentalist/coherence-report.js`) the designed-vs-built table + doc-health flags (length-cap violations, SPEC sprawl) + inventory summary to markdown. The subcommand (`bin/documentalist/document-review.js`) writes **EXACTLY** `docs/coherence-review.md` (a regenerable, tracked dashboard with a "do not hand-edit" banner) and is **strictly read-only beyond that one file** (an integration test asserts `git status` shows only that path — the safety heart of detect-before-act). Opt-in **`--with-claude`** layers an LLM commentary pass via the `MMD_DOCUMENT_REVIEW_CMD` spawn seam (rendered under its own heading — it never mutates the deterministic table), with a **graceful honest fallback** to the deterministic report when claude is absent/non-zero/empty (never a fabricated classification — L-021, universal §VI). Dispatch mirrors the document-* contract (`bin/mmd.js` + USAGE + `SUBCOMMANDS`). The acceptance test is reproducing the manual gap audit: on MMD itself it correctly flags all six big rocks (auto-handoff, Dream Expander, Plan-Review, Bundle A Security, full Documentalist, polymorphic Reality Check) as unbuilt/partial, the `MAKE_MY_DREAMS.md` cap violation, and the SPEC sprawl. The roadmap was reordered so **v0.7.b deepens *detection*** (per-claim DRIFT/conformance — truth over tidiness) and **active compaction** (archive the root SPECs, shard the oversized docs) slides to **v0.7.c**, the *act* face granted once detection is trusted. See [ADR-034](./docs/adr/034-documentalist-coherence-review.md).
- **Documentalist DRIFT / conformance check (`mmd document-review`, v0.7.b)**: the Documentalist's primary value is keeping docs **true**, not short. `mmd document-review` gains a **"## Drift / conformance"** section that scans the operational truth docs and flags where what a doc *claims* no longer matches what was **built** — **detect-before-correct, flag-only (it NEVER edits a doc)**. Two new pure modules: `lib/documentalist/doc-refs.js` (`extractDocRefs(text)` — line-aware, never-throws extraction of the artifacts a doc CLAIMS exist: `lib/`/`bin/`/`test/`/`docs/` `.js`/`.md` paths, backticked `mmd <subcommand>` mentions, `ADR-NNN`, bare `lib/<module>`; **distinct in purpose** from the grounding extractor `lib/here-mode/extract-file-refs.js`, which is input-focused and ignores `.js`) and `lib/documentalist/conformance.js` (`checkArtifactConformance` → dangling refs that don't resolve `{doc,line,ref,kind,reason}`; `checkFactConformance` → **bounded** stale-fact mismatches only — explicit `N subcommands/ADRs/(active) lessons` counts + "current/latest version X" vs the v0.7.a inventory, ignoring historical "as of vX"/"in v0.2.x" narrative — both pure, never throw, **labelled heuristic**). `lib/documentalist/coherence-report.js` renders the section (dangling references + stale facts + an opt-in `--with-claude` **semantic-drift** sub-pass via the `MMD_DOCUMENT_REVIEW_CMD` seam, **honest fallback** — never a fabricated "conformant"); `bin/documentalist/document-review.js` wires it, staying **strictly read-only beyond `docs/coherence-review.md`** (asserted). **Precision is the priority** (a drift section that cries wolf is useless): fenced code blocks + placeholder paths (`0NN-slug.md`) are skipped, subcommands are captured only inside inline code, fact conformance runs **only on the living current-state docs** (README/CLAUDE/HANDOVER — ADRs and `lessons-learned.md` are point-in-time records whose counts were true when written, so they are scanned for dangling *code* refs only), the subcommand authority is derived from the **real `bin/mmd.js` dispatch** (truth over tidiness — `mmd lessons` is dispatched yet missing from the `SUBCOMMANDS` export), and **negated/hypothetical/future** command mentions ("no standalone `mmd judge`", a "future `mmd doctor`", the v0.7.c "`mmd document-compact`" plan) are suppressed by a not-a-claim guard. On MMD itself it reports **3 dangling references + 0 stale facts** (two code files removed when `ship` was retired, still cited in historical records; one rejected-alternative `mmd init` in an ADR), with **zero** false positives on the dozens of valid refs — and it dogfooded itself, catching two stale ADR counts in README/HANDOVER mid-slice (corrected, so the live scan is now clean). Auto-*correcting* drift and compaction stay future (v0.7.c). See [ADR-035](./docs/adr/035-documentalist-conformance-drift.md).
- **Documentalist active compaction (`mmd document-compact`, v0.7.c)**: the Documentalist's first **action**. v0.7.a *detected* the root `SPEC_V*.md` sprawl and v0.7.b *checked* the docs' truth; `mmd document-compact` clears the sprawl by archiving the root SPECs into `docs/specs/` with an index and rewritten references — **act on the safe thing before the hard thing** (archiving is mechanical + fully reversible via `git mv`; the higher-risk **semantic** compaction — sharding the over-cap docs — is deliberately **deferred** until SPEC archival is trusted). A **pure planner** `lib/documentalist/compact.js` (`planCompaction({specs, existingArchive}) → {moves, indexMarkdown, referenceRewrites}` — `dst` under the `docs/specs/` folder, `indexMarkdown` newest-first by parsed version with each SPEC's title line, `referenceRewrites` mapping each root `SPEC_V0XX.md` token to its archived counterpart — plus `applyReferenceRewrites`, an **idempotent** exact-token transform that prefixes a reference **only when not already prefixed**, so no `docs/specs/docs/specs/`; both pure, no I/O, never throw, empty specs → empty plan, already-archived SPECs not re-planned). The subcommand `bin/documentalist/document-compact.js` does the I/O: `git mv` each root SPEC into `docs/specs/` (history preserved — `git log --follow` reaches the original), write a newest-first index there, and rewrite references (link targets, anchored links, prose mentions, backticked links) across tracked markdown **outside** the archive (a moved SPEC keeps its bare sibling cross-refs). **Safety contract**: move-only (**never** edits doc prose, never deletes), **idempotent** (no root SPECs → a clean no-op; second run changes nothing), **reversible**, preconditions validated **before any mutation** (a non-git repo → exit 5, an untracked SPEC → exit 6, nothing half-applied), and it does **not** auto-commit. `--dry-run` prints the plan and changes nothing (clean tree after). **Validated by its own Drift detector** (the v0.7.a/b synergy): after compaction a `mmd document-review` must show **no new dangling SPEC references**. New SPECs still land at the repo root per slice; a later run archives the shipped ones (the §6.4 periodic-consolidation model), so shipped SPECs live under `docs/specs/`. The live 34-SPEC archival on MMD is the operator's **post-merge** step (the slice validates on **fixture** git repos so it never moves its own in-flight `SPEC_V07C.md`). Dispatch mirrors the document-* contract (`bin/mmd.js` + USAGE + `SUBCOMMANDS`). See [ADR-036](./docs/adr/036-documentalist-active-compaction.md).
