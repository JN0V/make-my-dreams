# ADR-039 — `/mmd` Claude Code slash command: the operator playbook as a prompt template

**Status**: accepted
**Date**: 2026-06-01
**Slice**: v0.7.5 (`/mmd` operator slash command)

## Context

Driving MMD correctly is not just `mmd --here "<change>"`. A real Standard-engine
slice requires a stack of operational rules that live only in lessons-learned and
tribal memory:

- `MMD_TIMEOUT_MS=0` or the 30-min default kills the run mid-pipeline (L-016).
- `setsid`, not `nohup`, or the detached run dies with the shell (L-001).
- Monitor via `status.json` + git commits, never by tailing the buffered redirect
  log — `claude -p` does not flush stdout in real time (L-002).
- The dream must instruct **commit incrementally per AC** or a killed run loses
  everything (L-019).
- The spec-frozen directive (skip Party Mode, go straight to implementation) when
  a frozen SPEC is cited, to avoid the spec-polishing trap (L-016).
- A human-readable `--label` slug (universal §VII), a raised `MMD_DREAM_MAX_LEN`,
  bun + node 20 on `PATH`, honest reporting (ai-coding §I), verify-before-done
  (ai-coding §V), and on green an **offered** ff-only merge + annotated tag
  (commit-git §III–IV) rather than a silent merge.

Expecting an operator — or Claude in a fresh session — to remember all of this
every time is exactly the accessibility gap MMD exists to close. The information
already exists; it just is not *at hand* in the session.

## Decision

Ship a **`/mmd` Claude Code slash command** whose body is the MMD operator
playbook. `/mmd <intent>` instructs the session to **route** the intent to one of
three actions and run it with the full discipline encoded inline:

- **(a) a code change for the current repo** → launch `mmd --here` **detached**
  via `setsid` with every operational rule applied, then set up a per-run watcher
  and monitor honestly via `status.json` + git commits; on green, *offer* (never
  perform silently) a fast-forward-only merge + annotated tag.
- **(b) a greenfield dream** → `mmd "<dream>"`.
- **(c) a bare subcommand** (`discover`, `serve`, `document-review`, `handover`, …)
  → `mmd <subcommand>` directly.

It is **a prompt template, not a CLI change** — no `mmd` code is touched. The
single source of truth is the **tracked** file `assets/claude-commands/mmd.md`
(deliberately NOT under the gitignored `.claude/`, so it is reviewable and
versioned). `install-mmd.sh` materializes it **idempotently** into
`.claude/commands/mmd.md` next to the existing `bmad-adv-auto-dev` command: the
source dir is resolved from `BASH_SOURCE`, the copy is a `cp` (overwrites on
re-run), and a missing source degrades to an honest warning + skip rather than
fabricating the file (universal §VI).

## Consequences

- Opening a Claude Code session on any installed MMD repo gives you `/mmd`, which
  carries the L-001/L-002/L-016/L-019 discipline so you do not have to.
- The playbook is tracked and tested: `@unit` anchor tests
  (`test/unit/mmd-slash-command-template.test.js`) pin every operational-rule
  anchor so a future edit that silently drops one (e.g. removes `MMD_TIMEOUT_MS=0`)
  goes red; an `@integration` test
  (`test/integration/install-mmd-slash-command.test.js`) drives the install step
  on a temp target and asserts byte-for-byte materialization, idempotency, and the
  honest skip-when-absent path.
- The template is the operator's externalized memory: when a lesson changes, the
  playbook is the one place to update it.

## Alternatives considered

- **Generate the command inline via a heredoc** (as `bmad-adv-auto-dev` is) —
  rejected: a 150-line playbook embedded in the installer is unreviewable and
  un-unit-testable. A tracked source file is diffable, anchor-tested, and the
  single source of truth.
- **Put the source under `.claude/commands/`** — rejected: `.claude/` is
  gitignored (regenerated by `install-mmd.sh`), so the source would be untracked
  and wiped on the next install (the L-009/L-023 design-vs-substrate trap — harden
  from the committed layer).
- **Teach `/mmd` to run the merge/tag itself on green** — rejected: touching
  `main` is a human-in-the-loop gate (commit-git §I). The command *offers* the
  exact commands and lets the user confirm.
- **A new `mmd playbook` subcommand instead of a slash command** — rejected: the
  value is having the discipline *in the session* where the operator is already
  working; a slash command is the native Claude Code surface for that.
